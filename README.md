# Rumpus

An accessible MIDI file player for Windows, written in Rust. Rumpus plays Standard MIDI Files
through Windows MIDI Services (the `Windows.Devices.Midi2` API) and is built for keyboard and
screen reader users.

## Requirements

- Windows 11 with Windows MIDI Services installed and the MIDI service running.
- To build: Rust 1.98 or later with the MSVC toolchain, Visual Studio Build Tools with the C++
  workload, CMake and Ninja (both ship with Visual Studio). All `cargo` commands must run inside a
  Visual Studio Developer Command Prompt, because the `wxdragon-sys` crate downloads and builds
  wxWidgets from source with CMake and Ninja on the first build.

## Installing

Download `rumpus_setup-x64.exe` from the [releases page](https://github.com/LeonarddeR/rumpus/releases)
and run it. Setup can install Rumpus for all users or for the current user only, add Start Menu
and desktop shortcuts, and make Rumpus the default player for `.mid` and `.midi` files. It refuses
to install on a PC where Windows MIDI Services is unavailable or the legacy MIDI API mode is
selected.

Rumpus runs as a single instance: opening a MIDI file from Explorer, or running `rumpus.exe` with
file names while Rumpus is already open, adds the files to the playlist of the running window and
brings it to the front. They start playing right away unless something is already playing or
paused.

The `latest` prerelease on the releases page is rebuilt from every push to `main`.

## Building

1. Fetch the Windows MIDI Services SDK package once:

   ```powershell
   .\tools\fetch-sdk.ps1
   ```

   This downloads the `Windows.Devices.Midi2` NuGet package and extracts the metadata and the
   runtime DLL into `sdk/`. The build copies the DLL next to the executable.

2. Build and run:

   ```powershell
   cargo run -p rumpus -- path\to\song.mid
   ```

## Building the installer

The installer is an [Inno Setup 6](https://jrsoftware.org/isinfo.php) script in
`dist/windows/installer.iss`, driven by the `xtask` crate:

```powershell
cargo xtask build-windows
cargo xtask dist
```

The first command builds the release executable for `x86_64-pc-windows-msvc`. The second copies it
and the Windows MIDI Services runtime files into `target/dist/windows/x86_64/`, finds `ISCC.exe`
(the `ISCC` environment variable, then `PATH`, then the usual install directories) and writes
`target/rumpus_setup-x64.exe`. Setup runs `rumpus.exe --probe` before showing its first page; the
exit code says whether Windows MIDI Services is usable (0), the PC is in legacy API mode (1), the
service is unavailable (2) or the API is not installed (3).

## Testing

```powershell
cargo test -p rumpus-core
cargo test -p rumpus
cargo test -p rumpus -- --ignored
```

The ignored tests need the Windows MIDI Service and use its built-in diagnostic loopback
endpoints, so they run without any MIDI hardware.

## Regenerating the bindings

The WinRT bindings in `crates/rumpus/src/midi/bindings.rs` are generated by `windows-bindgen`
from `sdk/Windows.Devices.Midi2.winmd`, and the Win32 bindings for the single-instance pipe in
`crates/rumpus/src/win32.rs` from the metadata that ships with `windows-bindgen`. Both are
committed. After changing a filter list in `tools/bindgen/midi.txt` or `tools/bindgen/win32.txt`,
run:

```powershell
cargo bindgen
```

The SDK marks its methods `[noexcept]`, and released `windows-bindgen` 0.100 generates static
calls for such methods that do not compile. `tools/bindgen/Cargo.toml` therefore patches
`windows-bindgen` to a windows-rs checkout carrying the fix (branch `noexcept-static-methods`)
until it is upstream.

## Releasing

Releases are driven by [cargo-release](https://github.com/crate-ci/cargo-release)
(`cargo install cargo-release`). Nothing is published to crates.io; the tag is what CI builds and
publishes.

1. Record notable changes under `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md).
2. From a clean `main`, preview (dry run is the default), then execute:

   ```powershell
   cargo release patch             # or minor | major | <x.y.z>
   cargo release patch --execute
   ```

   cargo-release runs fmt, clippy and the tests of the non-GUI crates, bumps the workspace
   version, updates `Cargo.lock`, stamps `CHANGELOG.md`, commits, tags `X.Y.Z` and pushes.
3. The pushed tag triggers CI, which builds the executable, packages the installer and publishes
   the GitHub release with the changelog section as its body.

## Keyboard reference

| Command | Shortcut |
| --- | --- |
| Open files and play the first | Ctrl+O |
| Add folder | Ctrl+Shift+O |
| Remove from playlist | Delete |
| Play or pause | Ctrl+P (Enter on a playlist item plays it) |
| Stop | Ctrl+S |
| Previous or next track | Ctrl+Page Up, Ctrl+Page Down |
| Seek 5 seconds | Ctrl+Left, Ctrl+Right |
| Seek 30 seconds | Ctrl+Shift+Left, Ctrl+Shift+Right |
| Announce position | Ctrl+I |
| Tempo down, up, reset | Ctrl+Down, Ctrl+Up, Ctrl+0 |
| Transpose down, up, reset | Ctrl+Shift+Down, Ctrl+Shift+Up, Ctrl+Shift+0 |
| Refresh output devices | F5 |
| Exit | Ctrl+Q |

Tempo and transpose are also spin controls in the window. The MIDI output is chosen from the
Device menu, which lists every output as a radio item. The current position is shown as a text
field and announced on request, so playback never interrupts a screen reader.
