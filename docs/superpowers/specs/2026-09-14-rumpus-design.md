# Rumpus design

Rumpus is an accessible MIDI file player for Windows. It plays Standard MIDI Files through
Windows MIDI Services (the `Windows.Devices.Midi2` WinRT API) and presents a small wxWidgets
window built for keyboard and screen reader users.

## Scope of the first version

- Playlist: open files (multi-select dialog), add a folder, files given on the command line.
- Transport: play, pause/resume, stop, previous, next, seek by keyboard in 5 and 30 second steps.
- Tempo (25% to 400%) and transpose (-12 to +12 semitones), each as a spin control with shortcuts.
- Output device selection from a list of MIDI output ports, refreshable with F5. The selection
  is the only persisted setting.
- No fallback to older MIDI APIs. Without Windows MIDI Services, or in Legacy API mode, the app
  shows an error naming the cause and exits.

## Architecture

`rumpus-core` is a library with no UI or Windows dependency. It parses SMF files into a
timeline of events with absolute microsecond times, builds Universal MIDI Packet words, and
implements the transport: a state machine that schedules events against an abstract clock and
sink, tracks sounding notes, applies tempo and transpose, and silences notes on pause, stop and
seek. The playlist model and the config file live here too. Everything is unit-tested with a
fake clock and a recording sink.

`rumpus` is the application. A dedicated playback thread owns the Windows MIDI Services session
and connection and drives the transport. The UI thread sends it commands over a channel; it
reports state and position back through wxDragon's `call_after`. The window uses standard
controls with visible labels mirrored into accessible names, menu shortcuts for every command,
and a hidden live region for announcements.

## Playback timing

Windows MIDI Services schedules messages in the service by absolute timestamp, and nothing
scheduled can be cancelled. The transport therefore keeps only 500 ms of events scheduled ahead
and refills on every pump. Pause, stop and seek send note-offs for every sounding note plus
All Sound Off, Reset All Controllers and All Notes Off on each used channel, timestamped after
the last scheduled event, so nothing is left ringing. Seek replays the last program change,
controller values, pitch bend and channel pressure per channel before resuming.

## Bindings

The WinRT bindings are generated by `windows-bindgen` from the `Windows.Devices.Midi2.winmd`
shipped in the SDK NuGet package and committed to the repository. The runtime DLL is copied next
to the executable at build time because activation is app-local in the preview releases.
